## Refuted, in whole or in part

**C7, escaping.** Of the bypasses the audit shows, the ones that depend on where a
delimiter sits are fixed in #26. The rest of the finding asks the rule to tell whether
an input value would close its delimiter (`</ticket>` inside the ticket). The value is
known only at run time; a static rule cannot see it. The rule's documentation says so:
"A delimiter is not escaping: a value that contains the closing delimiter still closes
it, which no static rule can see."

**C16, timeouts.** A timeout still falls back. The first provider may still bill the
request, so a fallback can bill twice. Routing exists for availability, and a provider
that does not answer is the case it covers. The `fallsBack` docblock and the README
state the double-billing risk.

**C18, scope.** The compiler and runtime are not mutation-tested. A Stryker run over
them takes hours, and every surviving mutant needs a written reason. The report names
what its score does not cover, so the 96% cannot be read as a measure of that code.
The roadmap lists this work as not scheduled.

**C21, indentation.** The content of a triple-quoted string is sent as written. That
is documented (`docs/syntax-reference.md`: "Triple-quoted content is sent as written,
indentation included"), and `src/lexer/lexer.property.test.ts` checks that such a
literal reads back as exactly its text. Dedenting would change what every existing
prompt sends. It is a language decision, not a defect, and the roadmap lists it as
not scheduled.

**C22, integrity.** `compile` does not read `integrity.json`, by design: it is the
edit loop, and refusing a prompt changed since the last `install` would refuse every
edit. `check` is the gate, and its exit code on a modified prompt is tested. The
README gives the CI order: `check`, then `compile`.

## C23, process

The commit counts and co-authorship are accurate. That the author passes a
comprehension check before each merge cannot be verified from the repository. Each
work unit's report ends with five questions; recording the answers where a reviewer
can read them (for example in the pull request) is an open decision for the author.
