# PromptLang 2.0.0

The first release of `@promptlang/core` on npm. It follows an external audit
(2026-11-02) which found that the README's two headline features did not exist and
that the package could not be installed. Both are now true. Every capability the
README advertises in its comparison table and feature list has a passing test
listed in `docs/CLAIMS.md`.

```bash
npm install @promptlang/core
```

## What is new

- **Native tests.** `promptlang test` runs a file's `test` blocks against the
  generated TypeScript. It replays `mock:` responses by default, with no network.
  With `--live` it calls Anthropic after a cost estimate and your approval.
  Assertions: equality, `contains`, `matches`, `schema`. Exit codes:
  - `1` a test failed;
  - `3` a call failed and left a test without a verdict, labelled configuration
    error or provider failure.
- **SemVer for prompts.**
  - `@version` must be SemVer 2.0.0.
  - `import … requires "^1.0.0"` fails with `VersionMismatchError`.
  - `promptlang semver-check` compares each prompt's interface (parameters, output
    type, model) with a Git base, and fails when `@version` did not move enough.
  - `bun run demo` plays the whole scenario.
- **Cross-provider fallback.** `RoutingClient` takes `{ client, modelMap }`, so an
  Anthropic → OpenAI fallback sends OpenAI its own model name. `Retry-After` is
  honoured on 429.
- **Cost control.** `analyze --ai` and `test --live` print an estimate and ask
  before any paid call; `--yes` approves. The approved estimate is a spending cap
  enforced in code: a call whose estimated worst case would pass it is not sent.
  Neither command retries a call.
- **A measured AI linter.** `scripts/linter-eval.ts` runs the linter on 120
  labelled prompts (`evals/linter/`). On the test split it finds 44/45 and 45/45
  designed defects over two runs, but about 80% of its findings are false alarms
  (precision 20%, 95% CI 15–26%) and it flags every clean prompt. Figures and
  method: `docs/SYSTEM_CARD.md`. Read its findings as leads to check.
- **Fix: API keys in error messages.** Provider error messages quote the
  provider's body. The TypeScript runtime now removes the request's credential
  values (8 characters or more) from the error message and stack; the Python
  runtime removes the key from the provider's error message.
- **Python runtime.** Empty keys refused, HTTP errors raise typed
  `PromptClientError` subclasses, malformed responses raise `InvalidResponseError`.
  It does not retry; timeouts and connection failures raise `httpx` exceptions.
- **Anthropic API 2026-10-21.** Both runtimes send this version and never send
  `temperature`. The AI linter runs on `claude-haiku-5-5`.

## Breaking changes

See `docs/migration-guide.md` (1.2.0 → 2.0.0). In short:
- the package name and `exports` changed;
- generated code imports `@promptlang/core/runtime` (recompile);
- `@version` must be SemVer;
- `compile --target` accepts only `typescript` or `python`;
- `@temperature` is not sent to Anthropic.

`compile --emit-tsconfig` no longer writes `baseUrl`, which TypeScript 7 rejects.
A tsconfig emitted by an earlier version keeps it: re-run the command before
moving to TypeScript 7.

## Known limitations

- `eval` blocks are parsed but not executed.
- The AI linter's corpus is synthetic and its labels are set by construction.
  Precision counts every category nobody designed into a case as a false
  positive; until the labels' human check (`evals/linter/human-review/`) is done,
  some of those may be real defects, so 20% is a lower bound.
- The `promptlang` CLI needs Bun ≥ 1.2.20. The library and the runtime run on
  Node ≥ 20.
- `@promptlang/yaml-parser` on npm ships TypeScript sources, which Node cannot
  import (Bun and TypeScript bundlers can). `@promptlang/core` bundles its own copy
  and does not depend on it.

## `@promptlang/yaml-parser` 1.0.1 (security fix)

This release also publishes `@promptlang/yaml-parser` 1.0.1. In 1.0.0, a
`__proto__` key with a nested mapping became the prototype of the object
`parseYaml` returns, so a document could make keys it never set read as present
(a `__proto__:` key with `admin: true` nested under it gave
`result.admin === true` with `admin` absent from `Object.keys(result)`). 1.0.1
keeps `__proto__` as an ordinary key. Upgrade if you parse YAML you do not write
yourself. `@promptlang/core` 2.0.0 already contains the fix.

## Verifying the package

The tarball is published from `.github/workflows/release.yml` with npm provenance:
the package's npmjs.com page links each version to the workflow run that built it
(<https://docs.npmjs.com/generating-provenance-statements>).

The same tarball is attached to this release with its signed build provenance
(`promptlang-core-2.0.0.tgz.sigstore.json`):

```bash
gh attestation verify promptlang-core-2.0.0.tgz --repo matteogallo-ai/promptlang \
  --signer-workflow matteogallo-ai/promptlang/.github/workflows/release.yml
```
