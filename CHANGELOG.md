# Changelog

All notable changes to PromptLang are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [3.1.0] - 2026-11-07

### Security
- A value inserted between delimiters can no longer close or reopen them. Before,
  a ticket containing `</ticket>` closed the `<ticket>` tag around it, and the
  text after it read as the prompt's own. Generated TypeScript and Python now
  rewrite such a string, byte for byte the same in both languages, using the pairs
  `prompt-injection-risk` recognises around its placeholder:
  - `<name>`…`</name>` (and `<BEGIN>`/`<END>`): a `<` that starts `<name` or
    `</name`, in any ASCII case, with ASCII whitespace around the `/`, becomes
    `&lt;`; a longer name (`<tickets>`) is left alone;
  - `[[`…`]]`: `[[` becomes `[ [`, `]]` becomes `] ]`;
  - a code fence: each run of three or more backticks gets a space between each;
  - `---` lines: a line of three or more dashes gets a `\` before its first dash;
  - the ends of the value, which can sit next to another value or to the
    template's text: a trailing `<` that could still grow into `<name` or `</name`
    becomes `&lt;`; a `[`, `]` or run of backticks at either end gets a space on
    its outer side; a first or last line made only of dashes gets the `\`.

  Why these: the prompt reaches the model as plain text, so the rewrite keeps the
  value readable while the delimiter no longer appears in it; `- - -` is not used
  for dash lines because Markdown still reads it as a rule. A placeholder outside
  any delimiter is inserted as before, and the rule still warns about it. Unicode
  look-alikes (`＜`) and the template's own text are not rewritten.
  Code generated by 3.1.0 imports `neutralizeDelimiters` from
  `@promptlang/core/runtime` when a file needs it: recompile and upgrade together.
  Generated Python gets `neutralize_delimiters` in the `promptlang_runtime.py`
  written beside it.

### Added
- `neutralizeDelimiters` in `@promptlang/core/runtime`.

### Documentation
- The README fits on about one page: what PromptLang is, the quick example, the
  comparison table, installation. The reference moves to `docs/usage.md` (tests,
  versioning, Python target, configuration, providers), `docs/ai-linter.md` and
  `docs/how-this-was-built.md`.
- The AI linter's selection is tested against chance on the same 360 pairs,
  instead of setting two precision intervals side by side: 44 defects in its 217
  flagged pairs against 27.1 expected at random (hypergeometric p = 6.4e-10). Its
  limit is stated as such: specificity 45% (142/315).
- One sentence states how the code is built, the same wherever the repository
  speaks of it: "Built with coding agents: I write the specs, review the pull
  requests and their tests, and answer for what gets merged."

### Fixed
- `check:stale-narrative` did not read the packages' READMEs and did not know
  "will be removed": `packages/yaml-parser/README.md` said `ConfigParseError`
  "Will be removed in v2.0". The check now reads every package README and flags
  "will be removed / deprecated / dropped / renamed / replaced"; the sentence
  says "Deprecated".
- `parse`, `tokens`, `analyze` and `compile` printed `Could not read file: <path>`
  whatever the cause. They now name it with its errno code, for example
  `Could not read file: a.prompt: permission denied (EACCES)`; ENOENT, EPERM and
  EISDIR have their own wording (`src/cli/read-source.ts`).
- `bun run mutation` failed on a fresh clone (`ts.parseConfigFileTextToJson is not
  a function`): Stryker 10.1.1 rewrites `tsconfig.json` through the TypeScript 4–5
  API, which TypeScript 7 no longer has. The rewrite only moves `extends` and
  `references` paths, which `tsconfig.json` does not have, so `stryker.config.json`
  turns it off (`"tsconfigFile": ""`). CI runs a Stryker dry run on every pull
  request and the full run weekly (`.github/workflows/mutation.yml`).
- With a `python3` older than 3.11 (macOS ships 3.9), the tests that run generated
  Python failed with `ImportError: cannot import name 'NotRequired'`. They are
  skipped, and the reason is printed once (`tests/support/python.ts`); CI asserts
  Python 3.11+ before testing. CONTRIBUTING lists the prerequisite.

### Changed
- CI and the release build use the Bun in `.bun-version` (1.3.14), and a workflow
  rule fails a `setup-bun` step that names no version, so a tag is rebuilt with the
  Bun that built it. TypeScript is pinned to 7.0.2.
- The README's "Use it" says to run the example with Bun: Node does not run the
  generated `.ts` files as they are.

  (`evals/linter/findings-review/RESULT.md`): precision 30% (12/40, Wilson 95% CI

## [3.0.0] - 2026-11-03

The fixes for the F1 neutral audit (`docs/audit/`). Several refuse what 2.x
accepted silently: an answer outside its declared type, an incomplete answer,
outputs that overwrite each other, names the target cannot hold. Hence a major
version; `docs/migration-guide.md` (2.x → 3.0.0) lists what to change.

### Added
- `promptlang --version`, the same as `promptlang version`.

### Changed
- **`compile` refuses outputs that would overwrite each other, and writes
  nothing then** (breaking for folders that compiled before). Two files with the
  same name in different folders compiled to one output file: the last won,
  `index.ts` exported it twice, exit 0. `compile` now exits 1, before writing
  any file, valid ones included, when two sources would produce the same file
  (case ignored) or a file compile writes itself, or when two modules would
  export the same name (`sentiment` in two files, or `FooBarInput` from
  `foo_bar` and `fooBar`). Such files compile into different `--out` folders.
- **Python output files are renamed** to importable module names:
  `sentiment.v2.prompt` → `sentiment_v2.py` (`__init__.py` imported it as a
  package `sentiment`), `2x.prompt` → `_2x.py`, `class.prompt` → `class_.py`.
- **More names are compile errors**: reserved words where the generated code
  binds the name (`prompt delete`, a step `if`, a Python parameter `class`),
  any name with `-`, a Python name starting with `__`, a Python type, prompt or
  chain starting with `_promptlang_` (the generated helpers' prefix), a type, prompt or chain
  named after what the generated module imports (`PromptClient`, `Promise`,
  Python's `TypedDict`, `str`...), a TypeScript prompt or chain named
  `globalThis` or `undefined`, a step, prompt or chain named
  `client`, a step named after a prompt of the file, a parameter of its chain or
  an earlier step, and two declarations generating the same name (a type
  `FooInput` beside a prompt `foo`, Python enums `Foo` and `foo`). Each compiled to a
  module that does not parse or type-check, or that silently shadowed a name,
  with exit 0.
- **Generated headers no longer carry a `Generated at` timestamp**, so the same
  source and PromptLang version give the same bytes.
- **`prompt-injection-risk` warns in more places.** It now reads `system:` and
  `assistant:` sections, and `date` and text-bearing struct parameters, so a file
  that passed `analyze --strict` can now exit 1: for example a `{{tone}}` string
  parameter in a system prompt. Remedy: declare a value from a fixed list as an
  `enum`, or enclose the input in a delimiter pair.

- **Generated code checks every answer against its declared type** (breaking for
  code that relied on the old behaviour). Answers that used to pass now raise
  `InvalidOutputError`: a struct with a field the type does not declare, a field
  of the wrong type at any depth, a `number` not in decimal notation (`0x10`), a
  `date` that is not a real day (`2024-02-30`). The error has `prompt`, `errors`
  (at most 10, each at most 500 characters) and `output`; its message names the
  mismatches and never quotes the answer. In Python it subclasses `ValueError`,
  which the generated code raised before.
- **Generated TypeScript imports `parseOutput` from `@promptlang/core/runtime` as
  a value**, so it runs only with a runtime release that exports it. Before, it
  imported types only.
- **`expect schema` uses the same check**, so its messages give the kind of the
  wrong value (`got a string`) instead of quoting it, and count undeclared fields
  instead of naming them. `promptlang test` reports a mock outside the type as a
  failure before the test's assertions run.

- **`RoutingClient` falls back only when a provider could not serve the
  request** (outage, rate limit, timeout, network, 404, malformed body). A 400
  and any error that is not a `PromptClientError` used to send the same request,
  and the user's data, to the next provider; they are now thrown at once, like
  `AuthenticationError`.
- **A 404 from `AnthropicClient` or `OpenAIClient` raises `NotFoundError`**, as
  `OllamaClient` already did, instead of `InvalidRequestError`, so a model or
  endpoint one provider lacks falls back while a malformed request does not.
  Code that catches `InvalidRequestError` for a 404 catches `NotFoundError`.

### Fixed
- **The source path in generated headers and Python docstrings is escaped.** A
  newline, U+2028 or U+2029 in a file name ended the `//` comment and let the
  rest of the name run as code. Python docstrings name the source file instead
  of `<prompt>.prompt`.
- The `--help` example and the benchmark compile `docs/examples/*.prompt`:
  the folder also holds the demo's two versions of one prompt, which are
  alternatives and do not compile together.
- **`prompt-injection-risk` checks what encloses each input.** It accepted a
  section with any `---` or `<tag>` anywhere (`Answer in <b>bold</b>. Here is:
  {{x}}` passed), and never looked at `system:` sections. It now flags each text
  parameter (`string`, `date`, a struct with a text field, or an undeclared
  type) whose placeholder is not inside a delimiter pair, in every role, and no
  longer flags numbers, booleans or enums.
- **The example's injection test claimed a check it did not make.** Its comment
  said the mock checks the hostile text reaches the prompt inside `<ticket>`
  tags; nothing did. `tests/example-injection.test.ts` now checks it, and fails
  when the tags are removed.
- **`semver-check` treats declared type names as interface.** Renaming
  `type Category` to `type Kind` with the same values passed as a patch, because
  prompt contracts are compared by structure, yet the generated TypeScript and
  Python export `Category` by name and every consumer importing it broke. A
  declared type removed or renamed is now major, one added minor, and a changed
  type is judged like an output: narrowing an enum is major, adding an optional
  struct field minor (ADR 0002, amended).

- **Long-context prices in the estimate and the cap.** Claude Haiku 5.5 bills
  $0.50 / $2.50 per million tokens for a prompt over 100K tokens, five times its
  short-prompt rate, but every estimate and the spending cap priced it at
  $0.10 / $0.50, so a long call could pass the approved cap fivefold. Each call is
  now priced on the rate card its own prompt length selects: the estimate before
  approval, the worst case the cap checks, and the charge from reported usage.

- **A struct parameter reaches the model as JSON.** `{{ctx}}` with `ctx` a struct
  was sent as `[object Object]` from TypeScript and as a dict repr from Python;
  both now send `{"plan":"pro","seats":3}` (numbers as each language prints them).
- **Struct outputs are no longer cast unchecked.** Generated TypeScript
  `JSON.parse`d and cast the answer, and generated Python returned `json.loads`'
  result, so `{"amount": "not a number", "hacked": true}` came back typed as
  `ExtractedInvoice`. Both now call `parseOutput` / `parse_output` with the same
  rules and messages; one surrounding code fence is accepted.
- **Answers that cannot be checked are refused, not crashes.** A recursive type
  nested past the call stack raised `RangeError` (TypeScript) or
  `RecursionError` (Python); it is now an `InvalidOutputError`.
- **`OpenAIClient` sends `max_completion_tokens`, not `max_tokens`** (TypeScript
  and Python). GPT-5 and the o-series, which the routing example falls back to,
  answer `max_tokens` with a 400. The `@temperature` warning now says those
  models refuse any value but 1.
- **An incomplete answer is an error, not a result.** The TypeScript and Python
  runtimes returned whatever text a 2xx body held, so an answer cut at
  `max_tokens` (or a thinking-only body with no text), a refusal, or an empty
  answer reached the caller as a success; a struct prompt then failed later with
  a misleading parse error. They now raise `IncompleteResponseError` with a
  `reason` (`max_tokens`, `refusal`, `unexpected_stop`, `empty`) and the `usage`
  the provider billed. It is never retried and `RoutingClient` does not send it
  to a fallback, so a refusal is not routed around. `promptlang test --live`
  reports it as a configuration failure and still counts its tokens. Visible
  changes: an OpenAI body with `content: null` or blank text now raises instead
  of reading as `""`, and an OpenAI-compatible server that ends a successful
  answer with a non-standard `finish_reason` now raises `unexpected_stop`.

## [2.0.0] - 2026-11-03

Remediation after the 2026-11-02 external audit, and the first release of
`@promptlang/core` on npm.

**Why 2.0.0 and not 1.3.0.** Code written against 1.2.0 breaks in at least these
ways, each of which SemVer reserves for a major version:
- the package name (`promptlang` → `@promptlang/core`) and its `exports` (TypeScript
  sources under `./src` → built `./dist` with `types`/`import` conditions), so every
  import of 1.2.0 stops resolving;
- generated code imports `@promptlang/core/runtime`, so 1.2.0 output must be
  recompiled;
- `@version` must be SemVer and `compile --target` must be `typescript` or
  `python`, so files and scripts that 1.2.0 accepted are rejected;
- `AnthropicClient` no longer sends `temperature`, so the same file samples
  differently.

### Claimed but not true (corrected)
- README marked **Native tests** and **SemVer for prompts** ✅; neither was
  implemented. Both are now implemented (see Added), with their scope in the README.
- README marked **Multi-provider fallback** ✅; generated code sends the same model
  name to every provider, so Anthropic → OpenAI fallback failed. Now true:
  `RoutingClient` maps the model per provider (see Added).
- README marked the **AI-powered linter** ✅ and "unique"; it was only tested with a
  mocked client and had never run against the API. It is now measured on a
  labelled corpus (see Added): it finds almost every designed defect (recall
  44/45 and 45/45) but most of its findings are false alarms (precision about
  20%), and it flags every clean prompt. The README says so.
- The test badge said "626 passing": it counted `@promptlang/yaml-parser`'s 23
  tests twice (603 tests ran). Removed.
- `src/index.ts` exported only `VERSION = "0.1.0-alpha.0"` in v1.2.0.
- `docs/syntax-reference.md`, `docs/architecture.md`, `docs/migration-guide.md`,
  `docs/roadmap.md`, `docs/benchmarks.md`, `SECURITY.md` and `CONTRIBUTING.md`
  described syntax, commands, rules, config keys and pipeline stages that do not
  exist (e.g. `parallel` steps, cross-file chain calls, `promptlang test`,
  `defineRule`). All rewritten against the code.

### Changed
- **BREAKING:** package renamed `promptlang` → `@promptlang/core`; the CLI binary
  is still `promptlang`.
- `src/index.ts` exports `tokenize`, `parse`, `resolveGraph`, `resolveImport`,
  `compile`, `compilePython`, `analyze`, the error classes and AST types; `VERSION`
  is read from `package.json`.
- `.promptlang/integrity.json` keys are project-relative POSIX paths; legacy
  absolute keys are migrated on read.
- `.promptlang/manifest.json` (schema version 2) stores project-relative POSIX
  paths; version 1 manifests with absolute paths are migrated on read.
- `compile` rejects `.prompt` files with no declarations (exit 1).
- **BREAKING:** generated TypeScript imports `@promptlang/core/runtime` instead of
  `promptlang/runtime`, the package's real name; recompile existing output.
- **BREAKING:** `AnthropicClient` sends `anthropic-version: 2026-10-21` and never
  sends `temperature`, which that version rejects on every model. `@temperature`
  has no effect on Anthropic requests; OpenAI and Ollama still receive it. The key
  is still sent as `x-api-key`, which the API accepts on both versions.
- The examples are versioned 2.0.0 (their target model changed) and pass the
  project's own static analyzer: user input is delimited, with an untrusted-content
  instruction. Each example test has a `mock:` response.
- Examples, README, `init` template and the config default use `claude-opus-5-5`.
  They used `claude-opus-4.7`, which is not an Anthropic model ID (IDs use
  hyphens: `claude-opus-4-7`), and `classify-ticket.prompt` set `@temperature`,
  which Claude 4.7 and later reject.
- **BREAKING:** `compile --target` accepts only `typescript` or `python`. Any other
  value (e.g. `py`) used to produce TypeScript silently; it is now an error.
- `AnthropicClient` / `OpenAIClient` throw `TypeError` on an empty API key.
- The AI linter runs on `claude-haiku-5-5` (was `claude-haiku-4-5`, still active but
  ten times the price) with `max_tokens` 4096 and no `temperature`; `init` and the
  config default follow.
- The published package is built: ESM for Node ≥ 20 and Bun, with `.d.ts`
  declarations; `@promptlang/yaml-parser` is bundled in, so `@promptlang/core` has no
  runtime dependency. The CLI needs Bun ≥ 1.2.20.
- `analyze --ai`: a linter answer that is valid JSON of the wrong shape, or an
  issue without a string category, is an `ai:parse-failure` warning instead of
  "no issues".
- `compile --emit-tsconfig` no longer writes `baseUrl`, which TypeScript 7 rejects
  (TS5102). A `--runtime-path` that is neither absolute nor starts with `./` or
  `../` (either separator) is written with a leading `./`, since `paths` entries
  without `baseUrl` must be relative. A tsconfig emitted by an earlier version
  keeps `baseUrl`: re-run `compile --emit-tsconfig` before moving to TypeScript 7
  (deleting the line alone leaves a non-relative `paths` entry, TS5090).
- The repository builds and type-checks with TypeScript 7 (`typescript` ^7.0.2).

### Security
- The AI linter wraps each analyzed section in `<untrusted_prompt>` delimiters,
  escapes delimiter tags found in the text, and tells the model to treat the
  delimited text as data. The prompt text used to be inserted bare.
- Provider error messages no longer carry the API key: the TypeScript runtime
  removes the request's credential headers from the error message and stack, and
  the Python runtime removes the key from the quoted provider body. A provider or
  proxy that echoes the key used to leak it into terminals, CI logs and run records.
- `promptlang.yaml` (through `@promptlang/yaml-parser`): a `__proto__` key is kept as
  data. It used to be dropped, and a nested mapping under it became the parent
  object's prototype. The standalone package ships the same fix as 1.0.1.

### Added
- `@version` is validated as SemVer 2.0.0; an invalid value is a parse error
  positioned on the version string. **BREAKING** for files with non-SemVer values.
- `import "x.prompt" as X requires "<range>"`: `install` and `check` fail with
  `VersionMismatchError` when the imported `@version` does not satisfy the range
  (exact, `^`, `~`, `>`, `>=`, `<`, `<=`, space-separated AND).
- A syntax error in any file of the import graph is reported by `install` and
  `check` with the file path, instead of an uncaught exception.
- `promptlang semver-check [paths] [--base <ref>] [--json]`: compares each `.prompt`
  file's interface (parameters, output type, `@model`) with its version at a Git ref
  and exits 1 when `@version` was not bumped enough. CI runs it on `docs/examples`.
- `promptlang test <paths> [--json] [--live [--yes]]`: runs `test` blocks against the
  generated TypeScript, replaying `mock:` responses by default; `--live` calls
  Anthropic after printing a cost estimate and getting approval. The estimate
  counts every call a chain makes (steps, return expression and nested calls),
  values passed as numbers, booleans and enum members, and an earlier step's
  output inserted into a later one, assumed at most 6 characters per token; a
  longer answer makes the cap refuse the later call rather than overspend.
- `RoutingClient` accepts `{ client, modelMap }` entries, so an Anthropic → OpenAI
  fallback sends OpenAI its own model name; a provider with no mapping for the
  requested model is skipped.
- HTTP clients read `Retry-After` on a 429 (seconds or HTTP-date) into
  `RateLimitError.retryAfter`, and retries wait that long instead of the backoff;
  above 60 s the error is thrown without waiting.
- Python runtime: empty keys are refused, HTTP errors and malformed responses raise
  typed `PromptClientError` subclasses (the names TypeScript uses), and the Anthropic
  client sends version 2026-10-21 without `temperature`.
- `analyze --ai` prints a cost estimate and asks before any call (`--yes` approves;
  required without a terminal). It makes no retries, so the estimate counts each
  call once.
- `promptlang test` exits 3 when a failed call (any `PromptClientError`) left a
  test without a verdict, so an outage is never reported as a failed assertion. The
  report labels each one a configuration error (authentication, rejected request,
  unknown model) or a provider failure (timeout, network, rate limit, server,
  malformed response).
- Test syntax: `mock: "..."`, `expect contains:`, `expect matches:`, `expect schema`.
- A test whose `input` calls a prompt or chain the file does not declare, or with
  arguments that do not match its parameters, is a compile error.
- `compile` and `test` warn that `eval` blocks are parsed but not executed, and that
  `@temperature` is not sent to Anthropic.
- `.github/workflows/release.yml`: a `v*` tag runs CI, then `npm publish --provenance`;
  see `docs/RELEASING.md`. CI packs the tarball, installs it into an empty project
  and uses it from Node 20 and the current LTS (`scripts/consumer-test.ts`).
- `bun run demo`: the SemVer scenario end to end in a temporary Git repository.
- Optional parameters: `name?: Type` in prompts and chains (`name?: T` in
  TypeScript, `NotRequired[T]` in Python; an omitted one interpolates as "").
- `InvalidResponseError` for provider 2xx bodies that are not JSON or lack the
  documented fields (not retried; `RoutingClient` still falls back).
- `docs/CLAIMS.md`, `scripts/check-claims.ts`, `scripts/check-stale-narrative.ts`,
  `benchmarks/bench.ts`; Biome and knip configuration; CI jobs for each.
- `analyze --ai` and `test --live` enforce the approved estimate as a spending
  cap: a call whose estimated worst case would pass the approved total is not
  sent. `test --live` reports the test as a configuration error with no verdict
  (exit 3); `analyze --ai` reports the prompt as `ai:request-failure`.
  `test --live` refuses a model without a price before any call (exit 2).
- The AI linter is measured: `scripts/linter-eval.ts` runs it on `evals/linter/`
  (120 labelled cases, corpus 1.1.0), scores precision and recall with Wilson
  intervals, and writes an immutable record to `runs/live/` (checked by
  `SHA256SUMS`). `scripts/eval-report.ts` renders the measured blocks of
  `docs/SYSTEM_CARD.md` and `docs/SLO.md` from it.
- `docs/THREAT_MODEL.md`, `docs/RUNBOOK.md`, `docs/SLO.md`, `docs/SYSTEM_CARD.md`.
- The README's fresh-clone command runs in CI on every pull request (`fresh-clone`).
- Property-based tests and fuzzing with fast-check (a devDependency) on the lexer,
  the parser, `src/semver` and `@promptlang/yaml-parser`; see `docs/CLAIMS.md`.
- Mutation testing with Stryker on `src/lexer`, `src/parser` and `src/semver`:
  `bun run mutation`, run locally, results in `docs/mutation/`.

### Fixed
- `resolveGraph` / `resolveImport` used `Bun.file` and failed under Node.
- The stale-narrative check missed "requires the v0.6 …" in a `.prompt` comment.
- Tests that spawn `tsc` had bun's 5 s default timeout and flaked on cold runners.
- Python type mapper fell through from primitive to enum on an unknown primitive.
- Lexer: a string ending in a backslash at end of input or line is reported as an
  unterminated string, not as the escape `'\undefined'` or an escaped newline.
- Parser: an `import` after a declaration reports that imports must come first, as one
  after metadata already did, instead of "Expected a declaration ... but found 'import'".
- `promptlang.yaml`: a backslash in a single-quoted string is literal.

### Removed
- Dead exports reported by knip, orphan `.gitkeep` files, empty `src/linter/` and
  `src/compiler/typescript/` directories, the placeholder `build` script.

### Tags
- `v0.5.0-alpha.0` was missing from `origin`; it is now pushed, on the commit it
  always pointed to (`f6765ae`). History is not rewritten.

- `package.json` root now declares Bun workspaces (`"workspaces":
  ["packages/*"]`) and consumes the extracted parser via
  `"@promptlang/yaml-parser": "workspace:*"`.
- Every internal PromptLang import that previously targeted
  `../../config/yaml-parser` now targets `@promptlang/yaml-parser`
  (5 files: `src/config/config.ts`, `src/cli/commands/install.ts`,
  `check.ts`, `compile.ts`, `list.ts`).
- `tests/v1-stability.test.ts` was relaxed to permit first-party
  `@promptlang/*` workspace packages as dependencies. Third-party
  runtime dependencies remain forbidden — the zero-external-dep
  promise holds unchanged in spirit.

### Fixed

- `tsconfig.json` — the pre-existing `types: ["bun-types"]` reference
  (a legacy package name that is no longer resolvable via `@types/bun`)
  was corrected to `types: ["bun"]`. This surfaced only when running
  `bunx tsc --noEmit` and is unrelated to the extraction, but is bundled
  in v1.1.0 because it blocked the acceptance criteria for this release.

### Migration guide

External API-level consumers of PromptLang need to do nothing. Internal
tooling (compiled prompts, custom CLI wrappers) that imported
`ConfigParseError` from `../../config/yaml-parser` should:

1. Update the import path to `@promptlang/yaml-parser`, and
2. Rename `ConfigParseError` → `YamlParseError` (or keep the alias for
   one more release cycle).

  will replace its vendored copy of the parser with a proper `bun add
  @promptlang/yaml-parser` in its v0.2 release. That was the primary
